**quat-3d v0.1.0** is the first release of quat-3d. It is a game engine and
editor written in C++23. It renders with Vulkan 1.3 and Slang shaders, loads
glTF 2.0 models, and simulates physics with Jolt. AI assistants can drive it
over the Model Context Protocol (MCP). This release covers everything from
the start of the repository. It ships ready-to-run builds for Linux, Windows
and macOS (Apple Silicon), an engine SDK for building games in their own
repository, and a small sample game, Coin Collector, packaged with the
engine's own tools. quat-3d is licensed under the MIT License.

The engine is pre-1.0: scene files, the remote API and the MCP tools may
still change between 0.x releases.

## Highlights

- **AI assistants can build, tune, profile and debug worlds in the running
  engine.** `quat-mcp` is an MCP server for Claude Code, Claude Desktop and
  other clients, with 94 tools. Assistants can create entities, take
  screenshots, tune the look, set the weather and the time of day, push
  physics bodies and follow contact events, profile frames, write material
  shaders, Lua scripts and NPC behaviour trees, rebind input, steer the
  camera rig, and package a game. Eleven
  workflow skills (build a level, tune the look, set the weather, find a
  performance problem, and more) come with it, and a Claude Code plugin
  installs the server and skills in two commands
  (#2 #3 #17 #19 #22 #53 #54 #55 #64 #82 #83 #87 #111).
- **Weather and a real sky clock.** Gusts sweep through the grass, rain wets
  the ground and fills puddles, snow settles and melts, and clouds cast
  moving shadows. A world clock puts the sun where it really is for any
  date, time and place, so sunrises and sunsets happen on their own
  (#64 #87).
- **Realistic light and shadow.** Screen-space reflections, HDRI environment
  lighting, and specular that keeps rough metals bright. Sun shadows use
  four cascades fitted on the GPU, with soft PCSS edges, contact shadows and
  GTAO. Glass casts coloured shadows, and leaves and fences cut holes in
  theirs (#25 #70 #80 #89).
- **A cinematic camera.** Every camera has a physical lens (aperture,
  shutter, ISO, focal length, focus distance) for depth of field and motion
  blur. AgX, ACES and PBR Neutral tonemapping, colour grading with `.cube`
  look LUTs, and temporal upscaling (TAAU) (#34 #79).
- **Large GPU-generated worlds.** Terrain is synthesised and eroded on the
  GPU, dense grass grows around the camera, and trees and rocks are
  scattered and drawn with automatic instancing. Two showcases come with
  it: a mountain forest (`QUAT_DEMO=mountain`) and a forest clearing built
  from CC0 Poly Haven assets (#2 #3 #49 #91).
- **Make a game and ship it.** Write it in Lua 5.4 (sandboxed,
  hot-reloaded), with input action maps and a strategy camera rig, or in
  C++ against the engine SDK (`find_package(quat3d)`, `quat_add_game`) in
  its own repository. `quat-pack` turns a game into a standalone package
  with only the files it uses. The SDK and the Coin Collector sample are
  published as downloads next to this release (#22 #55 #111 #114).
- **A redesigned editor.** It has dark and light themes with crisp text in
  both, a command palette (Ctrl+P), a play / pause / step toolbar, gizmos
  with snapping, a property grid inspector, a console and a profiler panel
  (#52 #82 #88 #102).
- **Downloadable builds for all three desktop platforms, with quat-mcp
  inside.** Unpack, start the game, and point Claude Code at the bundled MCP
  server; no build tools are needed. Each archive is smoke-tested before it
  is published (#24 #96).

## Breaking changes

This is the first release, but anyone who used quat-mcp from the repository
before #83 should note that its MCP prompts were renamed to match the
skills. The arguments are unchanged.

|---|---|
| `build_world` | `build-level` |
| `tune_look` | `tune-look` |
| `write_material_shader` | `author-material-shader` |
| `write_game_script` | `write-gameplay-script` |
| `design_behavior` | `design-npc-behaviour` |
| `inspect_scene` | `inspect-scene` |
| `debug_session` | `debug-session` |

`debug-physics-glitch`, `playtest`, `set-weather` and
`find-performance-problem` are new. In Claude Code the prompts
appear as `/mcp__quat-3d__<name>`, and the plugin's skills as
`/quat-3d:<name>`.

## Rendering

- Objects that share a mesh and material are drawn as one instanced draw,
  automatically (#2).
- Point lights are culled on the GPU into view-space clusters, up to 4096
  lights per frame (#2).
- Saving a `.slang` shader recompiles it and swaps the pipeline in while the
  engine runs. A failed compile keeps the old pipeline (#3).
- `InstancedMesh` and `Scatter` place thousands of seeded trees or rocks on
  terrain from one entity (#3).
- Dense, wind-animated GPU grass with slope and height limits and distance
  level of detail (#3).
- Terrain tiles (noise plus hydraulic and thermal erosion) are synthesised on
  the GPU in milliseconds, with the CPU generator as fallback (#3).
- Four-cascade sun shadows, GPU-fitted and stable under camera motion. Also
  PCSS soft shadows, contact shadows, GTAO with bent normals, and terrain
  casting shadows. All of them are tunable in the Renderer panel (#25).
- glTF `MASK` materials cut out in the surface and in its shadow, with
  coverage-preserving mipmaps. Double-sided leaves are lit on both sides, and
  glass and blended materials cast coloured shadows (#70).
- KTX2 / Basis Universal textures are transcoded at load to BC7 / BC5 / BC4,
  or to ASTC on Apple GPUs. Meshes compressed with
  `EXT_meshopt_compression` and `KHR_mesh_quantization` load too (#43).
- `quat-cook` rewrites a glTF for shipping, with KTX2 textures and
  meshoptimizer-compressed geometry. On DamagedHelmet it needs about a
  quarter of the texture memory (#43).
- A velocity buffer covers meshes, instances, skinned meshes, grass and
  terrain. It feeds a TAAU upscaler with native, quality, balanced and
  performance render-scale modes (#34).
- GPU particles with depth collisions, soft edges, flipbooks, lighting from
  clustered lights, and order-independent transparency for smoke (#26).
- Emissive materials glow. Before, they rendered black in the deferred path
  (#19).
- A near-mirror highlight no longer turns into a black rectangle. HDR values
  are clamped, and bloom, TAA and exposure guard against NaN and Inf (#20).
- Weather, from one `weather` component (#64):
  - wind, cloud cover, rain or snow, and temperature. With accumulation on,
    rain soaks surfaces, snow settles at or below 1 °C and melts in the
    warm, and dry weather dries the ground;
  - a wind field computed on the GPU, with gust fronts and turbulence,
    bends the grass, and its gusts produce motion vectors;
  - wet surfaces darken and turn glossy, with puddles on flat ground, and
    snow covers upward-facing surfaces;
  - clouds cast moving shadows from a cloud shadow map;
  - a scene without weather renders exactly as before.
- A world clock (the `world_clock` component, or `QUAT_TIME`) places the sun
  for a date, time, latitude and longitude, using Meeus' algorithms checked
  against USNO almanac data. The sky then gives real sunrises and sunsets.
  The Moon's position and phase are computed too; drawing the night sky is
  ROADMAP R22.2 (#87).
- Screen-space reflections, traced through the depth pyramid and
  accumulated over frames, fall back to the environment where they miss
  (#80).
- HDRI environments: a Radiance `.hdr` panorama lights the scene and draws
  the sky (`QUAT_HDRI`, the Renderer panel, scene files or
  `environment.set`). Its sun becomes the shadow-casting sun light (#80).
- Energy-conserving specular: multiple-scattering GGX keeps rough metals
  bright, and normal-mapped surfaces stop reflecting the sky below their
  horizon (#80).
- A physical lens on every camera, with exposure from EV100, depth of field
  and motion blur. Depth of field and motion blur are off by default (#79).
- AgX, ACES (the default) and Khronos PBR Neutral tonemapping. Grading with
  white balance, contrast, lift / gamma / gain and saturation, `.cube` look
  LUTs (a sample `golden_hour.cube` is included), vignette, film grain and
  chromatic aberration (#79).
- Contact shadows no longer draw a dotted dark halo beside sphere
  silhouettes (#89, fixes #86).
- The mountain-forest showcase (`QUAT_DEMO=mountain`): a 2 km eroded terrain
  tile with about 11,500 trees, rocks and bushes scattered from 12
  procedurally generated models, and GPU grass (#49).
- Grass thins out over the last 8° below its slope limit instead of ending
  in a hard edge (#49, fixes #116).
- The cinematic forest clearing (`assets/scenes/cinematic_forest.json`) is
  built from CC0 Poly Haven models, a ground texture and an HDRI that a
  script downloads, checks and cooks. None of them are committed (#91).
- `quat-cook --simplify` builds level-of-detail meshes, thinning foliage
  cards instead of collapsing them, and `--blend-to-mask` makes blended
  foliage alpha-tested (#91).
- `scatter.mirror` mirrors a share of the scattered instances for variety
  (#91).
- A built-in frame profiler times every render pass and scene system on the
  CPU and GPU (average, p95, max). Builds with `ENGINE_PROFILE=ON` add
  Tracy 0.13.1, listening on loopback only. The release builds have the
  built-in profiler, not Tracy (#82).

## AI tooling / MCP

- `engine_remote` is a JSON-RPC 2.0 endpoint on 127.0.0.1 that AI tools use
  to drive the engine (`QUAT_REMOTE=<port>`) (#1).
- World commands create, update, re-parent and destroy entities and their
  components, and set the sun, sky and clouds. Batches can refer back to
  earlier results (#2).
- Further commands take screenshots as PNG, control the camera, spawn glTF
  models, play and stop the game, save and load scenes, and bake the navmesh
  (#2).
- `quat-mcp` is a Rust MCP server built on rmcp. It returns screenshots as
  images, reconnects when the engine restarts, and has setup docs for Claude
  Code and Claude Desktop (#2).
- Debugging tools read the engine log and Vulkan validation messages and
  report frame timings. They can also pause, single-step or slow the
  simulation, watch entities, cast physics rays and query navmesh paths (#3).
- Assistants can build, inspect and edit NPC behaviour trees, with
  validation errors for each node (#3).
- Exposure, bloom, anti-aliasing, shadows, AO, sky light and clouds can be
  tuned live, and materials can be overridden per entity. The values are the
  ones the editor shows and are saved with the scene. A `tune_look` prompt
  is included (#17).
- Assistants can write Slang material shaders. The engine compiles them,
  returns compiler errors with line numbers, and hot-swaps them while it runs
  (#19).
- Assistants can write and check Lua scripts (`script_*` tools, an API
  reference resource, and a `write_game_script` prompt) (#22).
- World-building tools set camera clip planes from the scene and edit
  terrain shading without regenerating it. They also report entity bounds,
  set models down on the ground, and take screenshots from any camera without
  moving yours (#53).
- `asset_search` / `asset_fetch` search and download CC0 models from Poly
  Haven, and record each model's licence (#53).
- Eleven workflow skills: `build-level`, `tune-look`,
  `author-material-shader`, `write-gameplay-script`, `design-npc-behaviour`,
  `debug-physics-glitch`, `playtest`, `inspect-scene`, `debug-session`,
  `set-weather` and `find-performance-problem`. Each is an Agent Skill with
  steps, checks and pitfalls (#83 #64 #82).
- quat-mcp serves the skills over the MCP skills extension
  (`skills/list`, `skills/get`, `skill://` resources). For clients without
  skills support, it generates MCP prompts of the same names from them
  (#83).
- A Claude Code plugin and marketplace in the repository:
  `/plugin marketplace add tomerab1/quat-3d`, then
  `/plugin install quat-3d@quat-3d`. It registers quat-mcp, which can be the
  binary bundled in this release, and installs the skills (#83).
- `resources/read` on a `skill://` URI the server does not serve returns
  `invalid_params`, like `skills/get` (#108).
- Physics control (#54):
  - `physics_get`, `physics_set` and `physics_apply` read and set
    velocities, motion type, friction and damping, and push bodies with
    impulses, forces and torques;
  - `physics_get_gravity` / `physics_set_gravity`;
  - `physics_raycast_all`, `physics_overlap` and `physics_shape_cast`;
  - `events_poll` follows contact and trigger events;
  - `character_move` walks a character controller;
  - joints are components, created and edited like any other.
- Profiling (#82): `profile_frame` ranks the costliest passes and systems by
  self time, `profile_capture` records frames with their spikes and causes,
  and `profile_counters` reports draws, triangles and memory. The
  `find-performance-problem` skill walks through them.
- Weather: `weather_get` / `weather_set`, and the `set-weather` skill (#64).
- Time of day: `time_get`, `time_set` and `time_skip`. While the clock drives
  the sun, `environment_set` refuses sun edits with an error that says so
  (#87).
- Game projects: `project_info`, `project_build` and `project_build_status`
  package the open game in the background (#55).
- Input and camera rig: `input_actions`, `input_inject`, `input_bind` and
  `input_context` read, drive and rebind the action map; `camera_rig_get`,
  `camera_rig_set` and `camera_rig_frame` steer the strategy camera (#111).
- `environment_set` loads an HDRI, `camera_set` takes a lens, and the
  `tune-look` skill covers tonemapping, the lens, depth of field, motion
  blur and grading (#79 #80).

## Editor

- A design system: dark and light themes with WCAG AA contrast, Inter,
  JetBrains Mono and Lucide icons, and DPI-aware sizing (#52).
- The command palette (Ctrl+P), the main toolbar and the shortcut list (F1)
  all come from one command registry. A status bar shows frame timing,
  selection and the MCP connection (#52).
- The Hierarchy has search, type icons, rename, duplicate and drag to
  re-parent. The Inspector has a property grid with reset-to-default and a
  searchable Add Component list (#52).
- The asset browser has breadcrumbs, grid and list views and search. A
  Console shows the engine log with level filters (#52).
- The layout and preferences are saved per project in `.quat/editor.ini`,
  and View > Reset Layout restores the default (#52).
- Fixes from the redesign's review (#88 #102):
  - a forced theme is not saved;
  - re-parenting under a zero-scaled parent, or one with a non-finite
    translation, is refused;
  - scene paths must be valid UTF-8;
  - symlinks that point outside the project, or that cannot be resolved,
    are not listed.
- The UI is blended in sRGB (gamma) space, as ImGui expects, so dark text on
  light panels is crisp in both themes (#102, fixes #92).
- A Profiler panel (View → Profiler) shows frame, CPU, GPU and wait times, a
  frame-time graph, and a sortable table of passes and systems with self
  time (#82).
- *File → Build & Export…* (Ctrl+B) packages the open game, shows
  quat-pack's progress and log, and offers "Show in folder" when it is done
  (#55).
- The Renderer panel gains Time of Day (date, a time scrubber, speed and
  city presets, sun and moon read-outs), Weather, an HDRI row and the view
  camera's lens. The inspector edits the World Clock, the camera lens and
  joints (#54 #64 #79 #80 #87).

## Gameplay

- Audio with miniaudio: music, sfx, ui and ambience buses, 3D positional
  sound with distance falloff, and streamed music (wav, flac, mp3) (#2).
- A visual node editor for behaviour trees (imgui-node-editor). JSON stays
  the asset format (#3).
- Inertialized animation transitions, two-bone foot IK with ground
  probing, and ACL clip compression within 0.1 mm of the source (#28).
- Lua 5.4 scripting (sol2) (#22):
  - `on_start`, `on_update`, `on_fixed_update`, `on_trigger_enter` /
    `on_trigger_exit` and `on_destroy` callbacks;
  - per-call instruction and memory limits;
  - hot reload that keeps the old version running when an edit is broken;
  - the Coin Collector demo
    (`QUAT_SCENE=assets/scenes/coin_collector.json QUAT_PLAY=1`).
- Physics (#54):
  - joints: fixed, point, hinge, slider and distance, with limits and
    motors, saved in scene files;
  - characters collide with each other, and dynamic bodies and sensors
    detect them (fixes #48);
  - shapes are reference-counted and character slots reused, so long Play
    sessions on streamed terrain no longer grow in memory (fixes #47);
  - gravity is a scene setting, saved with the scene;
  - contact and trigger events, one per pair of bodies.
- Lua's `time.clock()`, `time.set_clock{...}` and `time.skip(hours)` read
  and change the world clock (#87).
- Input action maps (#111):
  - button, 1D-axis and 2D-axis actions in JSON, bound to keys and chords,
    the mouse, screen edges and gamepads, with triggers (tap, hold, double
    click, drag) and modifiers (dead zone, invert, smoothing);
  - a context stack, so a menu can take over the controls it reads;
  - each fixed simulation step sees every press and release exactly once;
  - rebinding saved to a per-user file (`QUAT_INPUT_USER_FILE` overrides
    where);
  - Lua reads actions, and `input.vector`, `input.held_time`,
    `input.push_context` and `input.pop_context` are new. Existing scripts
    keep working.
- A strategy camera rig (`camera_rig`, `camera_rig_input`): orbit, pan with
  keys, stick or screen edges, grab-the-world drag, and zoom toward the
  cursor, all on critically damped springs. It follows the ground and stays
  within its bounds (#111).

## Platforms & packaging

- Windows (MSVC 2022) and macOS (Apple Silicon, MoltenVK) are built and
  tested in CI next to Linux (#24).
- Release archives (#24):
  - a Linux `tar.gz` with the C++ runtime bundled;
  - a Windows `zip` with every DLL and the MSVC runtime;
  - a macOS `.app` with MoltenVK and the Vulkan loader inside, ad-hoc
    signed.
- The game finds its data next to the executable, or in `QUAT_ASSET_ROOT`.
  Packaged builds contain no build-machine paths (#24).
- Every engine archive includes `quat-mcp`. It sits next to the game on Linux and
  Windows, and in `Quat3D.app/Contents/MacOS/` on macOS (#96).
- Every archive carries `LICENSE` (MIT) and `THIRD_PARTY_NOTICES.md`. The
  notices hold the licence text of every bundled library, font, runtime and
  Rust crate (#96).
- The Windows file watcher catches a rewrite that keeps the same size within
  one timestamp tick, so shader hot reload no longer misses edits (#24).
- Game projects (#55):
  - a `game.json` names the game, its start scene, window and icon;
  - `quat-player` runs a game without the editor. `quat-player-shipping`
    has no remote control compiled in, and CI checks the binary for it;
  - `quat-pack` collects the files a game references, cooks its models,
    writes a manifest with a SHA-256 per file, and lays out the package for
    its OS (an `.app` on macOS). It can smoke-test the result.
- The release publishes the Coin Collector sample for all three platforms,
  packaged with `quat-pack` and smoke-tested like the engine (#55).
- The engine SDK (#114, [`docs/sdk.md`](https://github.com/tomerab1/quat-3d/blob/v0.1.0/docs/sdk.md)):
  - a `quat3d-sdk-0.1.0-<os>` archive per platform: a relocatable CMake
    package a game finds with `find_package(quat3d 0.1 CONFIG)`, with the
    `quat3d::engine` and `quat3d::remote` targets and the stable headers;
  - `quat_add_game()` builds a game executable with its assets and
    material shaders, and a toolchain file selects the SDK's compiler
    family;
  - `bin/` holds `quat-cook`, `quat-pack`, `quat-player`,
    `quat-player-shipping`, `slangc` and `quat-mcp`; `deps/` the libraries
    the engine links, so a game never runs vcpkg;
  - `LICENSE` and `THIRD_PARTY_NOTICES.md` at the root and in
    `share/quat3d/`, where `quat-pack` takes them from for game packages;
  - while quat-3d is 0.x, a game needs an SDK of the same minor version.
- Every game package carries the engine's `LICENSE` and the
  `THIRD_PARTY_NOTICES.md` of the engine build it was packaged from, without
  quat-mcp's crates, which games do not ship. Without those notices
  `quat-pack` refuses to package (#96, #122).

## Stability & security

- A bug audit with fixes (#1):
  - malformed glTF files are validated before use;
  - out-of-bounds reads in animation sampling are fixed;
  - physics catch-up after a hitch is bounded;
  - orphaned physics bodies are cleaned up;
  - a bad scene file no longer crashes the engine and keeps the current
    scene;
  - render-graph synchronisation is fixed;
  - VRAM no longer grows on resize.
- Navigation, NPC, networking and TAA / exposure fixes from the audit
  (#2 #3).
- On macOS, the GBuffer and material pipelines failed to build on MoltenVK,
  hitting an upstream SPIRV-Cross bug with buffer-address pointers read
  through an array element. The previous-frame skinned positions are now a
  per-draw push constant, a portability test rejects the pattern, and CI
  checks the MSL translation of every shader (#103, #106).
- Crowd separation uses a spatial grid instead of comparing every pair of
  agents (#84, #94).
- The device and queue choice requires a GPU that can present, and
  explains why each GPU was rejected. Render-graph transitions and present
  barriers are fixed under synchronisation validation (#18).
- Physics bodies start at their real poses, and the physics demo's glass
  panel has a collider. The showcase opens framed on its content, and the
  terrain showcase sits on the terrain (#20).
- The remote endpoint always requires a session token (#63):
  - each run generates a random one in a file only your user can read, and
    quat-mcp reads it from there;
  - HTTP requests are dropped, so web pages in your browser cannot drive the
    engine.
- Audio clips are confined to the project, must be regular files, and are
  capped in decoded size. Frame time no longer jumps after the window is
  restored from minimised (#63).
- Network hosting listens on loopback by default (#74):
  - connections are capped;
  - clients must present a join token;
  - an authenticated player gets control of the character;
  - clients are rate-limited.
- Terrain fixes (#90):
  - one memory budget covers the whole terrain configuration, so a single
    remote call can no longer ask for tens of gigabytes;
  - erosion now relaxes steep slopes all the way down to the talus angle;
  - a cancelled tile no longer keeps generating on the CPU fallback.
- ImGui draw lists over 65,535 vertices render correctly. A child process
  that closes its output is still timed out (#65).
- CI builds and tests every change on Linux, Windows and macOS. It renders
  screenshots of every demo scene and skips docs-only changes
  (#1 #20 #24 #57).
- A reading list of the papers and talks behind the engine's techniques,
  each pointing to the code that implements it (#81 #85).

## Engine foundation

The engine core was built before the pull-request workflow (ROADMAP
"History", phases 1–14):

- **Rendering:** a Vulkan 1.3 render graph with automatic barriers and
  descriptor buffers, deferred PBR shading, and IBL. Also glass with
  refraction and absorption, clearcoat, a Hillaire sky with volumetric
  clouds, bloom, auto-exposure and filmic tonemapping.
- **Animation and physics:** glTF skeletal animation skinned in a compute
  pass, blending and a state machine. Jolt rigid bodies, a character
  controller and triggers.
- **World:** seeded procedural terrain with erosion, chunked LOD and
  streaming. Recast navmesh NPCs with behaviour trees and patrol routes.
  Client/server networking with snapshot replication and client-side
  prediction.
- **Editor:** a docked ImGui editor with gizmos, picking, play mode and JSON
  scene save / load.
- **macOS:** a descriptor-set fallback for drivers without
  `VK_EXT_descriptor_buffer` (MoltenVK).

Each smoke test unpacks the archive into a directory whose name contains a
space and non-ASCII characters. It requires a clean exit, a written
screenshot, and data found next to the executable. It also runs the bundled
`quat-mcp --version`, and requires `LICENSE` and `THIRD_PARTY_NOTICES.md`.
CI checks `quat-mcp` on Linux with fmt, pedantic clippy, tests, and a
licence check of every crate in its `Cargo.lock`. The release job builds it
on all three platforms with the same Rust toolchain.

The release also has the Coin Collector sample game for each platform:
`coin-collector-0.1.0-linux-x64.tar.gz`, `coin-collector-0.1.0-windows-x64.zip`
and `coin-collector-0.1.0-macos-arm64.zip`. Each is smoke-tested the same
way, without the `quat-mcp` check, and must also load its start scene. Its
`LICENSE` and `THIRD_PARTY_NOTICES.md` are checked like the engine's.

The engine SDK comes from the same build on each platform:
`quat3d-sdk-0.1.0-linux-x64.tar.gz`, `quat3d-sdk-0.1.0-windows-x64.zip`
and `quat3d-sdk-0.1.0-macos-arm64.tar.gz`. Before it is archived, the
release job installs it into a fresh prefix and builds and tests
`examples/sdk-consumer` against that prefix alone (`ctest -L sdk`). It needs
the same compiler family it was built with: clang with libc++ on Linux,
MSVC on Windows, Apple clang on macOS.

## Getting started

1. **Download** the archive for your platform below. See
   [Download a build](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#download-a-build)
   for each platform's requirements. Linux needs a Vulkan 1.3 driver and
   glibc 2.39 or newer. Windows needs a current GPU driver. macOS needs
   macOS 15 on Apple Silicon.
2. **Run** it:
   - Linux: `./game`.
   - Windows: `game.exe`.
   - macOS: `Quat3D.app`. Because the app is not notarized, allow it once
     under System Settings → Privacy & Security → *Open Anyway*.

   The editor opens with a showcase scene. Fly with the right mouse button
   held and WASD. Each archive's `README-RUN.txt` lists the options, and
   [Running](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#running)
   lists every environment variable.
3. **Connect Claude Code:** see [Use it with Claude Code](#use-it-with-claude-code).

Some switches to try (on macOS, start `Quat3D.app/Contents/MacOS/game` from
Terminal to set them):

| Variable | Effect |
|---|---|
| `QUAT_DEMO=mountain` | Open the mountain-forest showcase |
| `QUAT_SCENE=<file>` | Load a scene file instead of the showcase; `QUAT_PLAY=1` starts playing it |
| `QUAT_TIME=<ISO-8601>` | Start a world clock at that date and time, driving the sun (e.g. `2026-06-21T21:30+02:00`) |
| `QUAT_LATLON=<lat>,<lon>` | Where the clock is (default Paris) |
| `QUAT_TIME_SCALE=<n>` | How fast the clock runs (default 1; 0 freezes it) |
| `QUAT_HDRI=<file>` | Light the scene with a Radiance `.hdr` panorama (project-relative; none ships with the release) |
| `QUAT_GAME_CAMERA=1` | Play through the scene's own camera from the start. Any value turns it on, `=0` included (#119) |
| `QUAT_REMOTE=1` | Open the remote-control endpoint for AI tools on port 7878 |
| `QUAT_GAME=<folder>` | Open a game project (a folder with a `game.json`): scene files, scripts and the asset browser use it |
| `QUAT_NO_MUTABLE_SWAPCHAIN=1` | Draw the editor UI the way drivers without `VK_KHR_swapchain_mutable_format` do (same pixels; for checking that path) |

To build a game in its own repository against the SDK, see
[`docs/sdk.md`](https://github.com/tomerab1/quat-3d/blob/v0.1.0/docs/sdk.md).
To build the engine from source, see
[Building](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#building).

## Use it with Claude Code

The archive contains `quat-mcp`, the MCP server that lets Claude Code drive
the running game.

1. **Unpack** the archive. On macOS, run
   `xattr -dr com.apple.quarantine Quat3D.app` once, so that the app and the
   `quat-mcp` inside it may start.
2. **Start the game** with the remote-control endpoint (port 7878):
   - Linux: `QUAT_REMOTE=1 ./game`.
   - Windows (PowerShell): `$env:QUAT_REMOTE=1; .\game.exe`.
   - macOS: `QUAT_REMOTE=1 ./Quat3D.app/Contents/MacOS/game`.
3. **Connect Claude Code** to the bundled server. It is at:

   | OS | `quat-mcp` |
   |---|---|
   | Linux | `<folder>/quat-mcp` |
   | Windows | `<folder>\quat-mcp.exe` |
   | macOS | `<folder>/Quat3D.app/Contents/MacOS/quat-mcp` |

   Choose one of two ways:

   - **The quat-3d plugin (recommended).** It registers quat-mcp and
     installs the eleven workflow skills:

     ```
     /plugin marketplace add tomerab1/quat-3d
     /plugin install quat-3d@quat-3d
     ```

     When the plugin is enabled, Claude Code asks for three options:
     - `quat_mcp_command`: the absolute path from the table above;
     - `engine_port`: `7878`;
     - `project_root`: the game's data folder (see below).

     The skills appear as `/quat-3d:build-level`, `/quat-3d:tune-look` and so
     on, and Claude also picks them when a task matches.
   - **`claude mcp add`:** registers the server alone. Its skills are served
     over MCP, or as prompts such as `/mcp__quat-3d__build-level`:

     ```sh
     claude mcp add quat-3d -- /path/to/quat-3d-v0.1.0-linux-x64/quat-mcp \
       --project-root /path/to/quat-3d-v0.1.0-linux-x64
     ```

   Notes for both ways:
   - No token or port options are needed: quat-mcp reads the session token
     from the file the game writes.
   - The project root is the game's data folder: the unpacked folder, or
     `Quat3D.app/Contents/Resources` on macOS. `asset_fetch` saves the Poly
     Haven models it downloads there, so the game can load them. You can
     leave it out if you don't download models.
4. **Ask Claude** for something like *"add a red sphere above the ground and
   take a screenshot"*, or run `/quat-3d:build-level`. `/mcp` in Claude Code
   lists the server and its 94 tools.

See
[AI tools (MCP)](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#ai-tools-mcp),
[`tools/quat-mcp/README.md`](https://github.com/tomerab1/quat-3d/blob/v0.1.0/tools/quat-mcp/README.md)
and the
[plugin README](https://github.com/tomerab1/quat-3d/blob/v0.1.0/tools/quat-mcp/plugin/README.md)
for Claude Desktop, explicit tokens, the full tool list and the skills.

## Known issues and limitations

- **Unsigned builds.** The macOS app is ad-hoc signed but not notarized, and
  the Windows build is not code-signed, so SmartScreen warns. Signing is
  ROADMAP P7.
- **macOS 15 or later in practice.** The bundled Vulkan libraries come from
  Homebrew, even though the engine itself targets macOS 14. GPU tests on
  macOS do not gate CI yet: 8 of them still fail on MoltenVK, on tolerances
  and format expectations (#109).
- **The engine archives carry the editor and `quat-mcp` only.**
  `quat-cook`, `quat-pack` and the players are in the SDK archives. The
  editor's *Build & Export* and `project_build` look for `quat-pack` and
  `quat-player` next to the game, or at `QUAT_PACK` / `QUAT_PLAYER`.
  Fetching the cinematic forest scene needs the repository's script and a
  `quat-cook`.
- **macOS model downloads.** `asset_fetch` with the packaged app writes into
  `Quat3D.app/Contents/Resources`, which modifies the signed bundle. A
  project folder outside the app is a follow-up.
- **Software GPUs only in CI.** CI renders on Mesa lavapipe and the macOS
  runner's virtual GPU, and has no hardware GPU.
- **No undo / redo in the editor yet** (ROADMAP E1).
- **Asset loading.** Assets load synchronously (ROADMAP R1). The Vulkan
  pipeline cache is not saved, so every launch compiles all pipelines again
  (#76). FSR 2 is not integrated: TAAU is the only upscaler.
- **Visual.**
  - Grass ends in a visible ring at its draw radius (#27).
  - Distant terrain shading is flat (#15).
  - Ground below the horizon is a flat plane (#13). At sunrise and sunset
    it turns a saturated dark rust, with a hard step at the horizon (#98).
  - In the cinematic forest scene the grass is sparse: thin spikes over
    bare soil (#119).
- **An HDRI and the world clock disagree about the sun.** With both
  active, the HDRI's sun lights the scene, but `environment.get` still
  reports a clock-driven sun and `environment.set` refuses sun edits (#121).
- **Depth of field and motion blur** need the
  `shaderStorageImageExtendedFormats` device feature. Without it they are
  skipped, with a warning in the log (#79).
- **Lua.** Lua string patterns are not covered by the instruction limit, so
  a pathological pattern can stall a frame (#30).
- **Remote control and networking.**
  - Idle unauthenticated connections can hold the endpoint's client slots
    (#71). This is a local denial-of-service only.
  - Unauthenticated peers can fill a public host's connection cap (#75).
- **Poly Haven tools.** `asset_search` / `asset_fetch` were tested against
  offline fakes of the Poly Haven API, not against the live service.
