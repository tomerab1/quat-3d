**quat-3d v0.1.0** is the first release of quat-3d. It is a game engine and
editor written in C++23. It renders with Vulkan 1.3 and Slang shaders, loads
glTF 2.0 models, and simulates physics with Jolt. AI assistants can drive it
over the Model Context Protocol (MCP). This release covers everything from
the start of the repository. It ships ready-to-run builds for Linux, Windows
and macOS (Apple Silicon). quat-3d is licensed under the MIT License.

The engine is pre-1.0: scene files, the remote API and the MCP tools may
still change between 0.x releases.

## Highlights

- **AI assistants can build, tune and debug worlds in the running engine.**
  `quat-mcp` is an MCP server for Claude Code, Claude Desktop and other
  clients, with 51 tools. Assistants can create entities, take screenshots,
  tune the look, write material shaders, Lua scripts and NPC behaviour
  trees, read the log and step the simulation. Nine workflow skills (build
  a level, tune the look, playtest, and more) come with it, and a Claude
  Code plugin installs the server and skills in two commands
  (#2 #3 #17 #19 #22 #53 #83).
- **Shadows and ambient occlusion.** Sun shadows use four cascades fitted on
  the GPU, with soft PCF / PCSS edges. Contact shadows add small detail, and
  GTAO adds ambient occlusion with bent normals. Glass casts soft, coloured
  shadows, and alpha-cut leaves and fences cut holes in their shadows
  (#25 #70).
- **Temporal upscaling (TAAU) and GPU particles.** Motion vectors cover
  every draw type, and render-scale modes are available. Sparks, fire, smoke
  and dust are simulated in compute shaders, collide with the scene, and are
  lit by the sun and point lights (#34 #26).
- **Lua 5.4 gameplay scripting.** Scripts are sandboxed and hot-reloaded,
  with an API over entities, physics, input, audio and navigation. A playable
  Coin Collector demo is included (#22).
- **A redesigned editor.** It has dark and light themes, a command palette
  (Ctrl+P), a play / pause / step toolbar, gizmos with snapping, a property
  grid inspector and a console (#52 #88).
- **Large GPU-generated worlds.** Terrain tiles are synthesised and eroded on
  the GPU, and dense wind-animated grass is generated around the camera.
  Trees and rocks are scattered and drawn with automatic instancing
  (#2 #3).
- **Animation upgrades.** Clip switches use inertialized transitions, feet
  plant on uneven ground (foot IK), and clips are compressed with ACL (#28).
- **Downloadable builds for all three desktop platforms, with quat-mcp
  inside.** Unpack, start the game, and point Claude Code at the bundled MCP
  server; no build tools are needed. Each archive is smoke-tested before it
  is published (#24 #96).

## Breaking changes

This is the first release, but anyone who used quat-mcp from the repository
before #83 should note that its MCP prompts were renamed to match the
skills. The arguments are unchanged.

| Old prompt | New prompt |
|---|---|
| `build_world` | `build-level` |
| `tune_look` | `tune-look` |
| `write_material_shader` | `author-material-shader` |
| `write_game_script` | `write-gameplay-script` |
| `design_behavior` | `design-npc-behaviour` |
| `inspect_scene` | `inspect-scene` |
| `debug_session` | `debug-session` |

`debug-physics-glitch` and `playtest` are new. In Claude Code the prompts
appear as `/mcp__quat-3d__<name>`, and the plugin's skills as
`/quat-3d:<name>`.

## Rendering

- Objects that share a mesh and material are drawn as one instanced draw,
  automatically (#2).
- Point lights are culled on the GPU into view-space clusters, up to 4096
  lights per frame (#2).
- Saving a `.slang` shader recompiles it and swaps the pipeline in while the
  engine runs. A failed compile keeps the old pipeline (#3).
- `InstancedMesh` and `Scatter` place thousands of seeded trees or rocks on
  terrain from one entity (#3).
- Dense, wind-animated GPU grass with slope and height limits and distance
  level of detail (#3).
- Terrain tiles (noise plus hydraulic and thermal erosion) are synthesised on
  the GPU in milliseconds, with the CPU generator as fallback (#3).
- Four-cascade sun shadows, GPU-fitted and stable under camera motion. Also
  PCSS soft shadows, contact shadows, GTAO with bent normals, and terrain
  casting shadows. All of them are tunable in the Renderer panel (#25).
- glTF `MASK` materials cut out in the surface and in its shadow, with
  coverage-preserving mipmaps. Double-sided leaves are lit on both sides, and
  glass and blended materials cast coloured shadows (#70).
- KTX2 / Basis Universal textures are transcoded at load to BC7 / BC5 / BC4,
  or to ASTC on Apple GPUs. Meshes compressed with
  `EXT_meshopt_compression` and `KHR_mesh_quantization` load too (#43).
- `quat-cook` rewrites a glTF for shipping, with KTX2 textures and
  meshoptimizer-compressed geometry. On DamagedHelmet it needs about a
  quarter of the texture memory (#43).
- A velocity buffer covers meshes, instances, skinned meshes, grass and
  terrain. It feeds a TAAU upscaler with native, quality, balanced and
  performance render-scale modes (#34).
- GPU particles with depth collisions, soft edges, flipbooks, lighting from
  clustered lights, and order-independent transparency for smoke (#26).
- Emissive materials glow. Before, they rendered black in the deferred path
  (#19).
- A near-mirror highlight no longer turns into a black rectangle. HDR values
  are clamped, and bloom, TAA and exposure guard against NaN and Inf (#20).

## AI tooling / MCP

- `engine_remote` is a JSON-RPC 2.0 endpoint on 127.0.0.1 that AI tools use
  to drive the engine (`QUAT_REMOTE=<port>`) (#1).
- World commands create, update, re-parent and destroy entities and their
  components, and set the sun, sky and clouds. Batches can refer back to
  earlier results (#2).
- Further commands take screenshots as PNG, control the camera, spawn glTF
  models, play and stop the game, save and load scenes, and bake the navmesh
  (#2).
- `quat-mcp` is a Rust MCP server built on rmcp. It returns screenshots as
  images, reconnects when the engine restarts, and has setup docs for Claude
  Code and Claude Desktop (#2).
- Debugging tools read the engine log and Vulkan validation messages and
  report frame timings. They can also pause, single-step or slow the
  simulation, watch entities, cast physics rays and query navmesh paths (#3).
- Assistants can build, inspect and edit NPC behaviour trees, with
  validation errors for each node (#3).
- Exposure, bloom, anti-aliasing, shadows, AO, sky light and clouds can be
  tuned live, and materials can be overridden per entity. The values are the
  ones the editor shows and are saved with the scene. A `tune_look` prompt
  is included (#17).
- Assistants can write Slang material shaders. The engine compiles them,
  returns compiler errors with line numbers, and hot-swaps them while it runs
  (#19).
- Assistants can write and check Lua scripts (`script_*` tools, an API
  reference resource, and a `write_game_script` prompt) (#22).
- World-building tools set camera clip planes from the scene and edit
  terrain shading without regenerating it. They also report entity bounds,
  set models down on the ground, and take screenshots from any camera without
  moving yours (#53).
- `asset_search` / `asset_fetch` search and download CC0 models from Poly
  Haven, and record each model's licence (#53).
- Nine workflow skills: `build-level`, `tune-look`,
  `author-material-shader`, `write-gameplay-script`, `design-npc-behaviour`,
  `debug-physics-glitch`, `playtest`, `inspect-scene` and `debug-session`.
  Each is an Agent Skill with steps, checks and pitfalls (#83).
- quat-mcp serves the skills over the MCP skills extension
  (`skills/list`, `skills/get`, `skill://` resources). For clients without
  skills support, it generates MCP prompts of the same names from them
  (#83).
- A Claude Code plugin and marketplace in the repository:
  `/plugin marketplace add tomerab1/quat-3d`, then
  `/plugin install quat-3d@quat-3d`. It registers quat-mcp, which can be the
  binary bundled in this release, and installs the skills (#83).

## Editor

- A design system: dark and light themes with WCAG AA contrast, Inter,
  JetBrains Mono and Lucide icons, and DPI-aware sizing (#52).
- The command palette (Ctrl+P), the main toolbar and the shortcut list (F1)
  all come from one command registry. A status bar shows frame timing,
  selection and the MCP connection (#52).
- The Hierarchy has search, type icons, rename, duplicate and drag to
  re-parent. The Inspector has a property grid with reset-to-default and a
  searchable Add Component list (#52).
- The asset browser has breadcrumbs, grid and list views and search. A
  Console shows the engine log with level filters (#52).
- The layout and preferences are saved per project in `.quat/editor.ini`,
  and View > Reset Layout restores the default (#52).
- Fixes from the redesign's review (#88):
  - a forced theme is not saved;
  - re-parenting under a zero-scaled parent is refused;
  - scene paths must be valid UTF-8;
  - symlinks that point outside the project are not listed.

## Gameplay

- Audio with miniaudio: music, sfx, ui and ambience buses, 3D positional
  sound with distance falloff, and streamed music (wav, flac, mp3) (#2).
- A visual node editor for behaviour trees (imgui-node-editor). JSON stays
  the asset format (#3).
- Inertialized animation transitions, two-bone foot IK with ground
  probing, and ACL clip compression within 0.1 mm of the source (#28).
- Lua 5.4 scripting (sol2) (#22):
  - `on_start`, `on_update`, `on_fixed_update`, `on_trigger_enter` /
    `on_trigger_exit` and `on_destroy` callbacks;
  - per-call instruction and memory limits;
  - hot reload that keeps the old version running when an edit is broken;
  - the Coin Collector demo
    (`QUAT_SCENE=assets/scenes/coin_collector.json QUAT_PLAY=1`).

## Platforms & packaging

- Windows (MSVC 2022) and macOS (Apple Silicon, MoltenVK) are built and
  tested in CI next to Linux (#24).
- Release archives (#24):
  - a Linux `tar.gz` with the C++ runtime bundled;
  - a Windows `zip` with every DLL and the MSVC runtime;
  - a macOS `.app` with MoltenVK and the Vulkan loader inside, ad-hoc
    signed.
- The game finds its data next to the executable, or in `QUAT_ASSET_ROOT`.
  Packaged builds contain no build-machine paths (#24).
- Every archive includes `quat-mcp`. It sits next to the game on Linux and
  Windows, and in `Quat3D.app/Contents/MacOS/` on macOS (#96).
- Every archive carries `LICENSE` (MIT) and `THIRD_PARTY_NOTICES.md`. The
  notices hold the licence text of every bundled library, font, runtime and
  Rust crate (#96).
- The Windows file watcher catches a rewrite that keeps the same size within
  one timestamp tick, so shader hot reload no longer misses edits (#24).

## Stability & security

- A bug audit with fixes (#1):
  - malformed glTF files are validated before use;
  - out-of-bounds reads in animation sampling are fixed;
  - physics catch-up after a hitch is bounded;
  - orphaned physics bodies are cleaned up;
  - a bad scene file no longer crashes the engine and keeps the current
    scene;
  - render-graph synchronisation is fixed;
  - VRAM no longer grows on resize.
- Navigation, NPC, networking and TAA / exposure fixes from the audit
  (#2 #3).
- On macOS, the GBuffer and material pipelines failed to build on MoltenVK,
  hitting an upstream SPIRV-Cross bug with buffer-address pointers read
  through an array element. The previous-frame skinned positions are now a
  per-draw push constant, a portability test rejects the pattern, and CI
  checks the MSL translation of every shader (#103, #106).
- Crowd separation uses a spatial grid instead of comparing every pair of
  agents (#84, #94).
- The device and queue choice requires a GPU that can present, and
  explains why each GPU was rejected. Render-graph transitions and present
  barriers are fixed under synchronisation validation (#18).
- Physics bodies start at their real poses, and the physics demo's glass
  panel has a collider. The showcase opens framed on its content, and the
  terrain showcase sits on the terrain (#20).
- The remote endpoint always requires a session token (#63):
  - each run generates a random one in a file only your user can read, and
    quat-mcp reads it from there;
  - HTTP requests are dropped, so web pages in your browser cannot drive the
    engine.
- Audio clips are confined to the project, must be regular files, and are
  capped in decoded size. Frame time no longer jumps after the window is
  restored from minimised (#63).
- Network hosting listens on loopback by default (#74):
  - connections are capped;
  - clients must present a join token;
  - an authenticated player gets control of the character;
  - clients are rate-limited.
- Terrain fixes (#90):
  - one memory budget covers the whole terrain configuration, so a single
    remote call can no longer ask for tens of gigabytes;
  - erosion now relaxes steep slopes all the way down to the talus angle;
  - a cancelled tile no longer keeps generating on the CPU fallback.
- ImGui draw lists over 65,535 vertices render correctly. A child process
  that closes its output is still timed out (#65).
- CI builds and tests every change on Linux, Windows and macOS. It renders
  screenshots of every demo scene and skips docs-only changes
  (#1 #20 #24 #57).
- A reading list of the papers and talks behind the engine's techniques,
  each pointing to the code that implements it (#81 #85).

## Engine foundation

The engine core was built before the pull-request workflow (ROADMAP
"History", phases 1–14):

- **Rendering:** a Vulkan 1.3 render graph with automatic barriers and
  descriptor buffers, deferred PBR shading, and IBL. Also glass with
  refraction and absorption, clearcoat, a Hillaire sky with volumetric
  clouds, bloom, auto-exposure and filmic tonemapping.
- **Animation and physics:** glTF skeletal animation skinned in a compute
  pass, blending and a state machine. Jolt rigid bodies, a character
  controller and triggers.
- **World:** seeded procedural terrain with erosion, chunked LOD and
  streaming. Recast navmesh NPCs with behaviour trees and patrol routes.
  Client/server networking with snapshot replication and client-side
  prediction.
- **Editor:** a docked ImGui editor with gizmos, picking, play mode and JSON
  scene save / load.
- **macOS:** a descriptor-set fallback for drivers without
  `VK_EXT_descriptor_buffer` (MoltenVK).

on all three platforms with the same Rust toolchain.

## Getting started

1. **Download** the archive for your platform below. See
   [Download a build](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#download-a-build)
   for each platform's requirements. Linux needs a Vulkan 1.3 driver and
   glibc 2.39 or newer. Windows needs a current GPU driver. macOS needs
   macOS 15 on Apple Silicon.
2. **Run** it:
   - Linux: `./game`.
   - Windows: `game.exe`.
   - macOS: `Quat3D.app`. Because the app is not notarized, allow it once
     under System Settings → Privacy & Security → *Open Anyway*.

   The editor opens with a showcase scene. Fly with the right mouse button
   held and WASD. Each archive's `README-RUN.txt` lists the options, and
   [Running](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#running)
   lists every environment variable.
3. **Connect Claude Code:** see [Use it with Claude Code](#use-it-with-claude-code).

To build from source, see
[Building](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#building).

## Use it with Claude Code

The archive contains `quat-mcp`, the MCP server that lets Claude Code drive
the running game.

1. **Unpack** the archive. On macOS, run
   `xattr -dr com.apple.quarantine Quat3D.app` once, so that the app and the
   `quat-mcp` inside it may start.
2. **Start the game** with the remote-control endpoint (port 7878):
   - Linux: `QUAT_REMOTE=1 ./game`.
   - Windows (PowerShell): `$env:QUAT_REMOTE=1; .\game.exe`.
   - macOS: `QUAT_REMOTE=1 ./Quat3D.app/Contents/MacOS/game`.
3. **Connect Claude Code** to the bundled server. It is at:

   | OS | `quat-mcp` |
   |---|---|
   | Linux | `<folder>/quat-mcp` |
   | Windows | `<folder>\quat-mcp.exe` |
   | macOS | `<folder>/Quat3D.app/Contents/MacOS/quat-mcp` |

   Choose one of two ways:

   - **The quat-3d plugin (recommended).** It registers quat-mcp and
     installs the nine workflow skills:

     ```
     /plugin marketplace add tomerab1/quat-3d
     /plugin install quat-3d@quat-3d
     ```

     When the plugin is enabled, Claude Code asks for three options:
     - `quat_mcp_command`: the absolute path from the table above;
     - `engine_port`: `7878`;
     - `project_root`: the game's data folder (see below).

     The skills appear as `/quat-3d:build-level`, `/quat-3d:tune-look` and so
     on, and Claude also picks them when a task matches.
   - **`claude mcp add`:** registers the server alone. Its skills are served
     over MCP, or as prompts such as `/mcp__quat-3d__build-level`:

     ```sh
     claude mcp add quat-3d -- /path/to/quat-3d-v0.1.0-linux-x64/quat-mcp \
       --project-root /path/to/quat-3d-v0.1.0-linux-x64
     ```

   Notes for both ways:
   - No token or port options are needed: quat-mcp reads the session token
     from the file the game writes.
   - The project root is the game's data folder: the unpacked folder, or
     `Quat3D.app/Contents/Resources` on macOS. `asset_fetch` saves the Poly
     Haven models it downloads there, so the game can load them. You can
     leave it out if you don't download models.
4. **Ask Claude** for something like *"add a red sphere above the ground and
   take a screenshot"*, or run `/quat-3d:build-level`. `/mcp` in Claude Code
   lists the server and its 51 tools.

See
[AI tools (MCP)](https://github.com/tomerab1/quat-3d/blob/v0.1.0/README.md#ai-tools-mcp),
[`tools/quat-mcp/README.md`](https://github.com/tomerab1/quat-3d/blob/v0.1.0/tools/quat-mcp/README.md)
and the
[plugin README](https://github.com/tomerab1/quat-3d/blob/v0.1.0/tools/quat-mcp/plugin/README.md)
for Claude Desktop, explicit tokens, the full tool list and the skills.

## Known issues and limitations

- **Unsigned builds.** The macOS app is ad-hoc signed but not notarized, and
  the Windows build is not code-signed, so SmartScreen warns. Signing is
  ROADMAP P7.
- **macOS 15 or later in practice.** The bundled Vulkan libraries come from
  Homebrew, even though the engine itself targets macOS 14. GPU tests on
  macOS do not gate CI yet: 187 of 195 pass on MoltenVK, and the remaining
  tolerance and format-expectation failures are tracked in #109.
- **`quat-cook` ships as source only.** Build it from the repository to
  cook assets.
- **macOS model downloads.** `asset_fetch` with the packaged app writes into
  `Quat3D.app/Contents/Resources`, which modifies the signed bundle. A
  project folder outside the app is a follow-up.
- **Software GPUs only in CI.** CI renders on Mesa lavapipe and the macOS
  runner's virtual GPU, and has no hardware GPU.
- **Editor gaps.** There is no undo / redo yet (ROADMAP E1). In the light
  theme, dark text on light panels looks washed out (#92).
- **Asset loading.** Assets load synchronously (ROADMAP R1). The Vulkan
  pipeline cache is not saved, so every launch compiles all pipelines again
  (#76). FSR 2 is not integrated: TAAU is the only upscaler.
- **Physics.** Shapes and character slots are not released during a Play
  session, so long sessions on streamed terrain grow in memory (#47).
  Characters do not collide with each other (#48).
- **Visual.**
  - Grass ends in a visible ring at its draw radius (#27).
  - Distant terrain shading is flat (#15).
  - Ground below the horizon is a flat plane (#13).
  - A dotted dark halo can appear just outside sphere silhouettes (#86).
- **Lua.** Lua string patterns are not covered by the instruction limit, so
  a pathological pattern can stall a frame (#30).
- **Remote control and networking.**
  - Idle unauthenticated connections can hold the endpoint's client slots
    (#71). This is a local denial-of-service only.
  - Unauthenticated peers can fill a public host's connection cap (#75).
- **Poly Haven tools.** `asset_search` / `asset_fetch` were tested against
  offline fakes of the Poly Haven API, not against the live service.
